# Aion Corporation

Интернет-магазин персональных компьютеров с конструктором сборок.

**Из коробки:** витрина, конфигуратор с пресетами бюджета и выбором ОС, избранное, заказы, регистрация с подтверждением email и телефона, полноценная админка с журналом действий. Всё поднимается одной командой.

**Управляется из админки:** название сайта, логотип, favicon, контакты, соцсети, каталог, базовые сборки, пресеты, операционные системы — всё редактируется без единой правки в коде. Хотите магазин комплектующих, техники или другой ниши — берите проект как основу и меняйте содержимое под себя.

## Стек

- **PHP 8.1** — бэкенд
- **MySQL 8.0** — база данных
- **Apache** — веб-сервер
- **Docker Compose** — запуск одной командой

## Что внутри

### Для покупателя

- **Конфигуратор** — сборка ПК из комплектующих по девяти категориям: процессор, материнская плата, память, видеокарта, накопитель, блок питания, корпус, охлаждение и периферия. Сверху — пресеты бюджета, внизу — выбор операционной системы. Цена пересчитывается на лету, характеристики слотов видны прямо в выпадающих списках.
- **Витрина** — базовые сборки на главной: карточка с составом, характеристиками и итоговой ценой. При одной-трёх сборках — статичная сетка, при четырёх и больше — лента со стрелками.
- **Избранное** — сохранение конфигурации в профиль одним кликом; вернуться и продолжить сборку можно с любого устройства.
- **Заказы** — оформление заказа из сохранённой сборки, история заказов в профиле, смена статуса.
- **Аккаунт** — регистрация с подтверждением email и телефона, восстановление пароля, смена данных.
- **Тёмная тема** — переключатель в шапке; выбор хранится в cookie и переживает выход из аккаунта.

### Для администратора

- **Компоненты** — CRUD по девяти категориям: название, характеристики, цена, остаток, изображение.
- **Сборки витрины** — редактирование состава, названия и цены базовых сборок. Картинка берётся из выбранного корпуса.
- **Заказы** — список заказов, смена статуса, удаление.
- **Пользователи** — редактирование профиля, подтверждение email и телефона, удаление.
- **Конфигуратор** — пресеты бюджета и операционные системы: добавление, правка, удаление, порядок вывода.
- **Настройки сайта** — контакты (телефон, email, адрес на карте), соцсети, брендинг.
- **Брендинг** — название сайта, описание, логотип, генератор favicon из буквы и цвета либо загрузка своей PNG-иконки.
- **Файлы** — загрузка, привязка к сущностям, удаление.
- **Журнал действий** — все действия администратора с фильтрами по пользователю, типу действия и дате; ротация 90 дней.

### Легко заменить под свой проект

- **Контент** — вся витрина и каталог наполняются через админку или сид-скрипт (`SEED_DATA=1` для демо-данных).
- **Брендинг** — название, логотип, иконка, цвета темы в CSS-переменных.
- **Структура** — код разделён по слоям (`modules/`, `partials/`, `admin/`, `validation/`), так что подключить новую сущность или вкладку не составляет труда.
- **Схема БД** — миграции идемпотентны (`scripts/migrate.php`), новые таблицы и колонки добавляются при старте контейнера.

## Запуск

```bash
git clone https://github.com/nymphernus/aion-corp.git
cd aion-corp

cp .env.example .env      # обязательно поменяйте пароли
docker compose up -d --build
```

Сайт откроется на **http://localhost:8080**.

При первом старте контейнер сам создаёт схему, заводит администратора из `ADMIN_LOGIN`/`ADMIN_PASSWORD` и, если задано `SEED_DATA=1`, загружает демо-комплектующие.

Остановить: `docker compose down`.

## Администратор

Логин и пароль по умолчанию — в `.env.example`. Скрипт создания вызывается с `--if-not-exists`, поэтому повторные запуски ничего не сбрасывают.

Пароль хранится в базе как bcrypt-хеш; в `.env` он лежит открытым текстом только для первичного создания — после первого запуска его лучше убрать.

Создать администратора заново, минуя `.env`:

```bash
docker compose exec -it php php /var/www/html/scripts/create_admin.php
```

## Разделы сайта

| Адрес | Что там |
|---|---|
| `/` | витрина базовых сборок + конфигуратор |
| `/assembly.php` | страница сборки, покупка, сохранение в избранное |
| `/profile.php` | избранное, заказы, настройки аккаунта |
| `/admin.php?tab=...` | админка: `components`, `assemblies`, `orders`, `configurator`, `settings`, `files`, `log` |

Вкладка **«Журнал»** показывает все действия администратора: кто, когда, что, с какого IP. Записи старше 90 дней удаляются автоматически при старте контейнера.

## Тесты

Тесты ходят по HTTP на живой сайт — контейнеры должны быть подняты.

```bash
docker compose exec php php /var/www/html/tests/phpunit.phar \
  -c /var/www/html/tests/phpunit.xml --testdox
```

Перед прогоном стоит сбросить лимит попыток входа: тесты логинятся многократно, и без этого шестой запуск подряд упрётся в 429.

```bash
docker compose exec -T db mysql -uadmin -pdb_password_change_me shop_db \
  -e "DELETE FROM login_attempts;"
```

> Подставь свои значения из `.env`: `MYSQL_USER`, `MYSQL_PASSWORD`, `MYSQL_DATABASE`.

JS-тесты запускаются на хосте, зависимостей нет (нужен Node 18+):

```bash
node --test "src/tests/js/*.test.js"
```

## Разработка

Dev-режим монтирует `./src` в контейнер — правки видны сразу, без пересборки. Там же включается Xdebug для отладки из IDE на хосте:

```bash
docker compose up -d
```

Статический анализ — PHPStan объявлен в `composer.json`, но в репозиторий не установлен:

```bash
composer install
vendor/bin/phpstan analyse --level=5
```

Пути: на хосте `src/`, внутри контейнера — `/var/www/html/`. Команды через `docker compose exec` используют второй, локальные (`composer`, `vendor/bin/...`) — первый.

## Переменные окружения

Все значения по умолчанию — в `.env.example`.

| Переменная | Назначение |
|---|---|
| `MYSQL_*` | доступы к MySQL |
| `ADMIN_LOGIN`, `ADMIN_PASSWORD` | создание администратора при первом старте |
| `SEED_DATA=1` | загрузить демо-комплектующие |

## Обслуживание

Уборка брошенных сборок (те, что не сохранили в избранное и не заказали):

```bash
docker compose exec php php /var/www/html/scripts/cleanup_orphans.php --dry-run
```

Запускается автоматически один раз при старте контейнера. Cron не настроен.

Поиск дублей комплектующих после повторных сидов:

```bash
docker compose exec php php /var/www/html/scripts/find_duplicate_components.php
```

Скрипт только показывает группы дублей — удаление вручную после проверки.

```
└── assets/            css, js, images, fonts
```
